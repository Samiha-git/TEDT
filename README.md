# TEDT — Tunisia Educational Digital Twin (prototype)
التوأم الرقمي للمنظومة التربوية التونسية — نموذج أولي · Prototype de démonstration

> **All data shipped with this prototype is synthetic** (generated by `tedt_core/synthetic.py`, calibrated only to published national orders of magnitude). Simulation coefficients are **illustrative and uncalibrated**. Nothing here is an official statistic or a validated causal estimate.

## Install and run
```bash
cd tedt
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py          # opens http://localhost:8501
```
Language (Arabic/French) is switched from the sidebar; Arabic is RTL.

## Tests
```bash
pytest -q                     # 49 tests: metrics, validation, catalog, diagnostics, early warning, simulation
```

## Pages
1. Dashboard — national indicators and map
2. Data Observatory — documentary catalog (31 sources, 4 verification statuses), CSV/Excel import with validation
3. Learning Analytics — Bloom alignment and cognitive demand
4. Early Warning — aggregated risk model on synthetic anonymous records (prediction, not causation), fairness audit, small-cell suppression (<30)
5. Territorial Equity — interactive governorate map, weighted Gini, Lorenz curve, priority index
6. Policy Simulation Lab — class size, extra teachers, equipment budget, equity weighting; costs in units (1 unit = one teacher-year); presets, Monte-Carlo ranges (not confidence intervals), one-at-a-time sensitivity, scenario history (SQLite)
7. AI Policy Assistant — **demo mode, rule-based, no LLM**; answers cite sources
8. Reports — CSV and Arabic PDF export

## Replacing synthetic data with official files
Observatory page → upload CSV/XLSX. Required columns are checked by `data_store.SCHEMAS` (institutions: governorate, level, pupils, teachers, classes, equipment_index, mean_score, dropout_rate; results: governorate, deprivation_index, rural_share). Governorate names are normalised (FR/AR variants). Validation errors are shown before anything is used.

## Simulation model
Documented in the header of `tedt_core/simulation.py` (allocation weights, class-size/PTR/equipment effects, dropout response, cost accounting, additive partial effects). To calibrate: replace `Assumptions` defaults with values estimated from real evaluations.

## Plugging a language model into the assistant
Implement `AssistantBackend` in `tedt_core/assistant.py` (retrieval over the catalog and documents, then generation). Do not send personal data to external services; see the governance section of the strategy document.

## PDF fonts
Arabic PDF uses `arabic-reshaper` + `python-bidi` and a system font with Arabic glyphs; if none is found the PDF button is disabled with a message.

## Known limits
- No real data, no integration with ministry systems.
- Geographic boundaries: geoBoundaries ADM1 (CC BY 4.0).
- Early-warning model learns a declared synthetic rule; it demonstrates the method only.

## TEDT 2.0 — Lot 0 (provenance et fiabilisation)

Voir [`LOT0_TECHNICAL.md`](LOT0_TECHNICAL.md) pour les règles détaillées de provenance, de validation, de traitement des valeurs manquantes, d'agrégation, de reproductibilité des scénarios et de sécurité.

### Modes de données

- `DEMONSTRATION` est le mode par défaut et utilise exclusivement les jeux synthétiques.
- `REAL_DATA` n'utilise que les jeux importés et validés structurellement. Un jeu absent reste indisponible ; il n'est jamais remplacé par une donnée synthétique.
- Un import utilisateur porte le statut `imported_unverified` jusqu'à certification de son origine par le propriétaire institutionnel.
- Les imports de Lot 0 sont limités aux jeux agrégés `institutions` et `results`. Aucun dossier individuel d'élève ou d'enseignant ne doit être importé.

### Démarrage

```bash
pip install -r requirements.txt
streamlit run app.py
```

Le mode se choisit dans la barre latérale. L'activation d'un jeu importé en mode `REAL_DATA` exige une session institutionnelle authentifiée avec rôle `analyst` ou `admin`. Le module `tedt_core/security.py` définit le contrat d'autorisation, mais le raccordement OIDC/SSO n'est pas fourni dans Lot 0 : tant qu'il n'est pas intégré, l'activation des imports réels est volontairement bloquée dans l'interface.

### Tests

```bash
python -m pytest -q
python -m compileall -q app.py ui.py tedt_core views tests
```

La suite Lot 0 conserve les 49 tests initiaux et ajoute les tests de provenance, validation, imputation, agrégation, simulation, exports, historique et permissions.

## TEDT Education Data Foundation — Lot 1

Le premier socle de données est documenté dans `LOT1_FOUNDATION_TECHNICAL.md` et `LOT1_STEPB_VALIDATION.md`.

- Registre des sources : `data/foundation/source_register.csv`.
- Dictionnaire initial des indicateurs : `data/foundation/indicator_dictionary.csv`.
- Schéma SQLite : `data/foundation/schema.sql`.
- Base dédiée (créée à l'initialisation) : `data/tedt_foundation.sqlite`.
- Fichiers originaux importés : `data/staging/<batch_id>/`.

L'import générique CSV/XLSX est disponible dans l'onglet « Socle de données — Lot 1 » de l'Observatoire en mode `REAL_DATA`, sous réserve d'une session authentifiée analyst/admin. L'import conserve le fichier original et ses métadonnées ; le contrôle structurel ne vaut pas validation métier, autorisation juridique ou certification statistique. Aucun chargement automatique dans le Data Warehouse n'est effectué.

Le pilote INS RGPH 2024 (scolarisation 6–14 ans) est référencé, mais son classeur XLSX n'a pas pu être récupéré dans l'environnement de développement. Il n'est pas présenté comme une intégration réelle achevée.


## Identité visuelle TEDT

La charte graphique est centralisée dans `ui.py` et `.streamlit/config.toml` :
- fond général clair (`#F4F8FC`) et panneaux blancs/gris bleuté ;
- bleu nuit `#0D1B2A`, bleu acier `#1B4F72`, turquoise `#0FA3A3`, vert `#20C997`, ambre `#F5A623` ;
- Poppins pour les titres, Inter pour les textes, Noto Sans Arabic pour l'arabe (avec polices système de repli) ;
- logo institutionnel français/arabe sélectionné automatiquement selon la langue ;
- logotype TEDT original intégré dans l'en-tête, sans marque DataReady Studio.

Les logos du ministère sont conservés dans `assets/branding/`. Le chargement des polices Google est facultatif : en l'absence de connexion, les polices système de repli sont utilisées.

## Déploiement (GitHub + Render)
Le fichier `render.yaml` décrit le service web. Sur Render : *New > Blueprint*, choisir le dépôt GitHub.
Commande de démarrage : `streamlit run app.py --server.port $PORT --server.address 0.0.0.0 --server.headless true`.
Attention : sur l'offre gratuite, le disque est éphémère ; l'historique des scénarios (`data/tedt_scenarios.sqlite`) est réinitialisé à chaque redémarrage.
